# 원본으로 처음부터 편집하기 — 판단 기준과 함정

## 어떤 영상에 맞는 방식인가

OBS 같은 걸로 **화면 녹화 + 그린스크린 카메라**를 동시에 찍은 설명 영상(튜토리얼, 서비스 소개)에 맞춰져 있다.
두 파일은 같은 마이크 소리가 들어 있어서 소리 상관으로 싱크를 맞춘다(상관 0.98~1.0이 정상).
목소리는 카메라 파일 소리를 쓴다. 화면 녹화만 있거나 카메라만 있는 경우엔 scratch_timeline.py를 고쳐서 쓴다.

## 음성 인식(FFmpeg whisper 필터)

- 모델: whisper.cpp ggml 모델이 필요하다. `ggml-large-v3-turbo-q5_0.bin`(약 550MB, Hugging Face
  ggerganov/whisper.cpp)이 한국어 품질/속도 균형이 좋았다(실시간의 약 5배). 없으면 **사용자에게 묻고** 받는다.
  받은 모델은 `~/.cache/whisper/`에 두고 재사용한다.
- 긴 파일을 통째로 인식하면 문장 시간이 10~20초 단위로 뭉개지고, `max_len=1`(단어 단위)로 해도 단어 끝 시각이
  다음 공백까지 번진다. 그래서 **소리 크기로 말 덩어리(unit)를 먼저 자르고, 덩어리 사이에 2초 무음을 넣어 이어 붙인
  뒤 인식**한다. 단어는 **시작 시각** 기준으로 덩어리에 배정한다(scratch_prep.py가 이렇게 한다).
- 덩어리 가장자리의 짧은 단어("됩니다", "있어요")는 종종 빠진다. 덩어리 길이(초)와 글자 수가 안 맞으면 빠진 말이
  있다고 보고 앞뒤 맥락으로 판단한다.
- 무음 구간에서 "감사합니다."가 자주 지어내진다(환각). 소리 크기 지도와 대조해 실제 소리가 없으면 무시한다.
- 필터 옵션 안의 경로는 `:`를 `\:`로 이스케이프해야 한다(Windows 드라이브 문자).

## 무엇을 자르나 (판단 규칙)

1. **같은 말을 다시 시작한 경우**: 연속된 덩어리가 같은 단어로 시작하거나 내용이 겹치면 한 문장을 여러 번 시도한
   것이다. **끝까지 말한 마지막 시도**를 남긴다. 사람은 앞 시도가 마음에 안 들어서 다시 말하기 때문이다.
   예) "제가 장애인 활동 지원에 관한 프로그램을 / 제가 / 제가 장애인 주간활동 서비스에 관한 … 영상을 켰습니다" → 셋째만.
   예) "1명당 월 / 5,000원 / 받을 예정입니다 / 당사자 1명당 이용자 / 이용자 1명당 월 5,000원을 받을 예정입니다" → 마지막만.
2. **말하다 끊긴 문장**(어미 없이 멈춤 → 다른 문장 시작)은 끊긴 부분을 버린다. 덩어리 중간에서 끊겼으면
   trim(구간 안 가장 조용한 20ms)으로 자른다. 단어 시각 ±0.3초 창을 주고, 필요하면 소리 크기 막대를 찍어 본다.
3. **혼잣말·군소리**: "음?", "흠흠", "어", "완전 다 안 나오네", "헉 나 … 등록했는데" — 시청자에게 하는 말이 아니면 뺀다.
4. **화면 조작 중 긴 침묵**: 뺀다. 화면이 툭 넘어가는 점프컷이 생기지만 설명 영상에서는 자연스럽다.
5. **실패한 시연을 다른 파일에서 다시 찍은 경우**: 파일 경계를 넘어서 본다. 앞 파일 끝의 시연이 꼬였고 다음 파일이
   같은 설명으로 시작하면 앞쪽을 통째로 버린다(이번 프로젝트: 핸드폰 화면 시연).
6. **발음·말투만 다른 두 완결 시도**는 소리로 판단하기 어렵다 → 마지막 것을 고르고, 보고서에 "판단이 갈릴 수 있는 곳"으로
   시각과 함께 적어 사용자가 고를 수 있게 한다.
7. 내용 자체를 줄이는 판단(설명이 길다, 곁가지다)은 사용자 취향이다. 기본은 **내용은 남기고 군더더기만** 뺀다.

## 확인 루프 (꼭 한다)

`scratch_edl.py --check`로 이어 붙인 소리를 다시 인식해 **시청자처럼 처음부터 읽는다.** 남은 반복("어떤 직원을
선택해서 / 어떤 직원을 선택해서"), 끊긴 말, 이상한 이음새가 바로 보인다. 고친 곳은 `--window 시작:길이`로 그 부분만
다시 확인한다. 이번 프로젝트에서는 첫 판에서 4곳, 둘째 판에서 2곳을 더 고쳤다.

## 편집 습관(프로필)

무엇을 남기고 어떤 화면 구성을 쓸지의 **기본값은 `editing_profile.md`**에 있다. 편집 결정 전에 함께 읽는다.
사용자가 새 습관을 알려 주면(예: "항상 표지로 시작해") 그 파일에 추가한다.

## 화면 구성

- 시작/마무리 인사처럼 화면이 의미 없는 구간은 타이틀 이미지를 배경으로 쓴다(decisions["title"]).
- 카메라는 오른쪽 아래가 기본. 카메라 자리 아래 화면이 복잡하고(가장자리 밀도) 반대쪽이 확실히 비어 있을 때만
  옮기고, 다시 돌아올 때도 같은 조건을 요구해서 왔다갔다하지 않게 한다.

## 개인정보

- `privacy_review.py`로 4초 간격 장면 모음을 만들어 **전부 직접 본다.** 시연용으로 입력한 이름(홍길동, 이몽룡 등)은
  괜찮지만, 예전 실제 보고서·내보낸 엑셀·직인/서명에는 실제 이용자·직원 정보가 있다.
- 실제 기록인지 애매하면(예: 대상자명은 바꿨는데 제공인력 칸은 실제 이름) 가리는 쪽을 택한다.
- 고정된 칸/열은 `rect` + 시간창으로, 스크롤되는 문서는 색 기준점(베이지 헤더 칸, 빨간 직인)을 매 프레임 찾는
  detector로 처리한다(`privacy_detector_example.py`).
- 모자이크는 `block_px`(고정 픽셀 칸)를 쓴다. 프리미어식 "영역을 N칸으로 나누기"는 가는 띠에서 칸이 1px까지
  얇아져 글자가 읽힐 수 있다.
- 직원 이메일, 기관 가입 코드, 전화번호처럼 판단이 필요한 것은 보고서에 따로 적어 사용자에게 묻는다.

## 이번 프로젝트 결과(참고치)

원본 43분 → 26분 8초(139클립). 사용자가 프리미어로 직접 한 편집(24분 23초)의 94.5%와 같은 구간을 골랐다.
차이는 (1) 사용자가 설명 일부를 더 덜어낸 것, (2) 반복된 말 중 다른 시도를 고른 3곳.
