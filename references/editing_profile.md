# 편집 프로필 (기본값)

이 파일은 **한 제작자의 편집 습관**을 적은 프로필이다. 스킬을 처음 만든 제작자(그린스크린 카메라 + 화면 녹화로
사회복지 기관용 앱 설명 영상을 만드는 사람)의 프리미어 편집 3편과 블라인드 편집을 비교해 확인했다.
다른 사람이 쓴다면 이 파일을 자기 습관으로 바꾸면 된다 — 사용자가 "앞으로는 이렇게 해줘"라고 하면 여기에 추가한다.


프리미어로 직접 편집한 결과와 블라인드 편집을 비교해 확인한 규칙이다(2026-08 장애인주간활동 94.5%, 2026-07 구글캘린더
92.3%, 2026-03 차량운행일지 89.2% 일치). 사용자가 따로 말하지 않으면 아래를 기본값으로 쓴다.

1. **같은 말을 두 번 이상 완결해서 말했으면 거의 항상 나중 것을 쓴다.** 앞 시도가 완결이어도 마찬가지다(3편 모두에서
   확인: "직인을 등록할 수가 있어요", "일반 설정에 들어갑니다", "코드를 입력하고 기관 참여하기", "인공지능 훈련해야").
   화면을 찾느라 같은 문장을 여러 번 하면 화면이 맞게 잡힌 마지막 시도가 남는다.
2. **파일 경계를 넘는 다시 하기를 찾는다.** 앞 파일 끝의 설명이 다음 파일 첫머리에서 다시 시작되면("그래서 여기
   예약하기를 누르거나…") 앞 파일 쪽을 버린다.
3. **녹화 순서대로 간다.** 끝에 따로 녹화한 요약을 앞으로 끌어와 오프닝 훅으로 쓰지 않았다. 요약을 쓸지, 어디에 둘지는
   사용자에게 묻는다.
4. **시작은 표지 이미지 약 5초**(카메라와 목소리는 그대로 위에 나온다): `decisions["intro"]`. 폴더(하위 폴더 포함, 예:
   `pdf/…/슬라이드1.PNG`, `제목-없음-*.png`)에서 표지·슬라이드 이미지를 먼저 찾는다. 마무리 인사에 마지막 슬라이드를
   깐 적도 있다(`decisions["outro"]`) — 있으면 제안한다.
5. **URL을 말할 때는 URL 이미지**(예: `제목-없음-1.png`)를 그 문장 동안 배경으로 깐다(`title.ranges`).
6. **따로 찍은 핸드폰 화면 녹화는 기능 소개 부분에 B-roll로**, 1.25~1.5배속으로 빠르게, 화면 중앙에 작게(약 44%) 넣었다
   (`broll` 의 `speed`, `scale`). 앱 홍보 영상 검색 화면 같은 짧은 녹화는 그 내용을 말할 때 0.8배속으로.
7. 연결어 조각("나와요. 이 화면은 기관의", "로그인 누른 다음에")은 꽤 남긴다 — 군소리·혼잣말만 확실히 지우고 짧은 연결
   조각은 지나치게 깎지 않는다.
8. 카메라: 아래 모서리, 크기 33~40%, **위쪽은 거의 자르지 않는다**(머리가 잘리면 안 됨 — scratch_timeline.py의
   `--crop auto`가 머리 끝을 찾아 자른다). 좌우 위치는 화면 내용에 따라 오간다.

2026-10 손빠르미 설치·사용 안내(Claude가 편집, 사용자가 보고 고침)에서 사용자가 고른 것:

9. **소개 말 동안은 움직이는 화면**: 인사·소개(처음 약 20초)에 멈춘 화면 녹화가 깔리면 "심심하다"고 했다. 표지 약
   5초 + 같은 서비스의 홍보 영상(시연 장면, 소리 없이)을 소개 말이 끝날 때까지 깔았다. 마무리도 홍보 영상을 깔아 그
   영상의 끝 화면(설치 안내)으로 끝냈다. 폴더에 홍보 영상이 있으면 먼저 제안한다.
10. **끝은 페이드 아웃**(화면·소리 1.5초), **소리는 −16 LUFS**로 맞춘다.
11. 짧게 검게 바뀌는 프레임(새 탭 열림 등)은 거슬려 한다 — 완성본마다 `black_frames.py`로 찾아 없앤다.
12. 다른 서비스 시연(드라이브)이나 곁가지 설명(자막·전체 화면·멈춤)은 덜어냈고, 유튜브 시연은 앞(설치 직후)으로
    옮겼다 — 시연 순서는 "가장 익숙한 것부터"를 선호한다. 순서를 바꿀지는 대본을 읽고 제안만 하고 사용자가 정한다.
